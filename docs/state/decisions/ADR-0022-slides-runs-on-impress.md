# ADR-0022 — Zaldros Slides работает на движке LibreOffice Impress

Дата: 2026-08-28. Статус: принято.

## Решение

Третий раз тот же шов (ADR-0013, ADR-0020): своё окно, чужой движок. `apps/slides` открывает
headless LibreOffice по UNO; слайды, макеты, заполнители, заметки докладчика, переходы, PPTX/ODP и
экспорт в PDF — работа Impress.

**Это первое офисное приложение, проверенное на живом движке.** `libreoffice-impress-nogui` в
песочнице есть, поэтому тесты действительно создают колоду, пишут PPTX, читают её обратно и
экспортируют PDF (`%PDF` в первых четырёх байтах).

## Что выяснилось у работающего движка, а не из документации

1. **Заметки опознаются по типу фигуры, а не по сервису.** `supportsService(
   "com.sun.star.presentation.NotesShape")` возвращает False на той самой фигуре, у которой
   `getShapeType()` — ровно эта строка. Спросили движок; поверили движку.
2. **Переходы — это `TransitionType`, а не `FadeEffect`.** Свойства `FadeEffect` у страницы в
   Impress 7.4 просто нет; старый API документирован, но не существует.
3. **Фильтр PPTX не переносит переход.** Колода, сохранённая в PPTX и открытая заново,
   возвращается без перехода — это записано отдельным тестом, чтобы никто не заявил обратного.
   Макет после круга тоже меняет номер: PPTX хранит не наши номера макетов.

## Честность

Макет без заполнителя (пустой слайд) **отказывает** в тексте, а не рисует свободную надпись:
приложение не подменяет структуру презентации собственной. Слайда с несуществующим номером нет —
это ошибка, а не тихое ничего. Без движка окно рисуется, колода пуста, и в строке состояния
написано, какого пакета не хватает.

## Чего нет

* Режима докладчика и показа слайдов (нужен полноэкранный вывод и второй монитор).
* Анимаций внутри слайда, тем оформления, вставки картинок и таблиц на слайд.
* Правки текста прямо на слайде: пока правятся заголовок, текст и заметки через модель.
