# ADR-0016 — «Диспетчер задач» читает ядро, и только когда открыт

Дата: 2026-08-28. Статус: принято.

## Задача

Нужен настоящий диспетчер задач: приложения, процессы, службы, ЦП, память, GPU, диск, сеть,
время работы, автозагрузка; завершение процесса, поиск, сортировка, графики. Требование владельца
дословно: **никаких выдуманных метрик**. И второе, из ADR-0014: никакого фонового опроса.

## Решение

`backend/zaldros_backend/processes.py` — один фасет над файлами ядра: `/proc/<pid>/{stat,status,
cmdline,io,fd}`, `/proc/stat`, `/proc/meminfo`, `/proc/diskstats`, `/proc/net/dev`,
`/sys/class/drm`. Ни `ps`, ни `top`, ни psutil: это три способа прочитать те же файлы, и два из
них — новая зависимость в ISO.

Три правила, из которых всё вытекает.

1. **Нагрузка — это разность двух выборок.** Одно чтение `/proc/<pid>/stat` говорит, сколько
   процесс съел с загрузки, а не сколько он ест сейчас. `Sampler` хранит предыдущую выборку;
   в первой выборке `cpu is None`, и колонка «ЦП» показывает «—». Ноль вместо неизвестного —
   это выдуманная метрика, и тест на это есть.
2. **Опроса нет, пока окно закрыто.** `ProcessModel.setActive(true)` (из `onVisibleChanged`
   окна) запускает таймер 2 с; закрытие останавливает его. Закрытый диспетчер стоит ровно ноль
   чтений `/proc` — проверяется тестом со счётчиком выборок, а не обещанием в документации.
3. **«Приложения» — это не догадка по имени процесса.** Раздел появляется, только когда кто-то
   передал множество pid'ов, владеющих окнами; такое множество знает только композитор. Без него
   `apps_available=false` и причина «нет списка окон от композитора» — вместо эвристики, которая
   назовёт приложением любой процесс с GUI-подобным именем.

## Что показывается и откуда

| Данные | Источник |
|---|---|
| Процессы: имя, командная строка, пользователь, состояние, потоки, RSS | `/proc/<pid>/{stat,status,cmdline}` |
| ЦП процесса и всей машины, по ядрам | разность двух выборок `/proc/<pid>/stat` и `/proc/stat` |
| Память, подкачка | `/proc/meminfo` (MemAvailable, а не MemFree) |
| Диск: скорость чтения/записи | `/proc/diskstats`, разделы не считаются внутри своих дисков |
| Сеть: приём/отдача | `/proc/net/dev`, без `lo` |
| Ввод-вывод и открытые файлы процесса | `/proc/<pid>/io`, `/proc/<pid>/fd` (недоступно ≠ ноль) |
| GPU | `/sys/class/drm/card*/device/gpu_busy_percent` — только amdgpu его отдаёт; i915 и nouveau перечисляются с причиной, а не с числом |
| Время работы | `/proc/uptime` |
| Автозагрузка | freedesktop autostart, `Hidden=` в пользовательской копии `~/.config/autostart` |
| Службы | уже существующий фасет `services` (systemd, ADR-0014) |

## Завершение процесса

`end(pid, force=False)` шлёт SIGTERM, `force=True` — SIGKILL; pid ≤ 1 отклоняется. Ответ ядра
возвращается дословно: EPERM — это «недостаточно прав», а не «готово». UI печатает эту строку в
статусной полосе. Проверено настоящим убийством настоящего `sleep`, а не моком сигнала.

## Дизайн

Окно закрыто по умолчанию, кнопка на панели задач появляется только пока оно открыто, Alt+Tab
обходит только открытые окна (иначе он бы *запускал* диспетчер). Семь кадров — рабочий стол,
«Пуск», быстрые параметры, «Параметры», «Проводник», центр уведомлений, светлая тема — попиксельно
идентичны кадрам с HEAD `89975d5`. Паритет 41/41.

## Чего нет

* Подлинного снимка Windows 11 Task Manager в библиотеке эталонов нет — геометрия взята из уже
  измеренных токенов Windows 11 (командная панель 48, рельс 190, строка 32). Это записано в
  `system/theme/win11-reference.json → task_manager` как производная, а не как измерение.
* Раздел «Приложения» пуст без композитора (см. правило 3); графики — только ЦП и память, история
  живёт в памяти окна и обнуляется при закрытии.
* Ничего не проверено на живом железе: у песочницы нет GPU с `gpu_busy_percent`, нет разделов с
  реальным вводом-выводом. Первое доказательство — отчёт о загрузке ISO.
