# ADR-0018 — Сеть, звук, Bluetooth и питание: пути записи, а не только чтения

Дата: 2026-08-28. Статус: принято.

## Задача

ADR-0014 и ADR-0015 дали чтение и базовые переключатели. Не хватало действий, ради которых
пользователь вообще открывает эти панели: подключиться к сети по паролю, включить VPN, увидеть DNS
и прокси, спарить устройство Bluetooth, убавить громкость одному приложению, переключить режим
питания.

## Решение

Дописаны существующие фасеты, новых слоёв не появилось.

| Действие | Как |
|---|---|
| Подключение к Wi-Fi с паролем | NM `AddAndActivateConnection`, SSID как `ay`, у открытой сети блока безопасности нет вообще |
| Отключение устройства и деактивация подключения | NM `Device.Disconnect`, `DeactivateConnection` |
| Сохранённые профили и VPN | NM `Settings.ListConnections` + `GetSettings`, фильтр по типу `vpn`/`wireguard` |
| DNS | `IP4Config.NameserverData` активного подключения, а не `resolv.conf` (там на systemd-resolved всегда 127.0.0.53) |
| Прокси | переменные окружения — единственное, чему на Linux реально подчиняются приложения; в `source` так и написано |
| Сопряжение Bluetooth | `Device1.Pair`, затем `Trusted=true`; удаление — `Adapter1.RemoveDevice`, потому что пару держит адаптер |
| Громкость приложения | `wpctl status` → потоки, `wpctl get-volume <id>` на каждый; запись зажата в 0–150 % |
| Устройство записи | `wpctl` источники, выбор по умолчанию |
| Режимы питания | power-profiles-daemon, имя шины `org.freedesktop.UPower.PowerProfiles` (в 0.20 переехало с `net.hadess.PowerProfiles`) |

Строки «Параметров» под это создаются **по факту машины**: один переключатель на каждый профиль
VPN, один регулятор на каждый звуковой поток. Заранее нарисованных строк для профилей, которых
нет, не существует — это ровно тот случай, ради которого в ADR-0015 у каждого состояния есть
`available` и `reason`.

## Что проверяется

Тесты идут против моков служб на настоящем `dbus-daemon` и проверяют **то, что ушло на шину**:
SSID уходит байтовым массивом (классическая ошибка клиентов NetworkManager), у открытой сети нет
секции `802-11-wireless-security` (пустая заставила бы NM просить несуществующий ключ), `Pair`
сопровождается `Trusted`, `RemoveDevice` уходит адаптеру, громкость 900 % превращается в 1.50.

## Чего нет

* Агента сопряжения BlueZ нет: устройство с PIN-кодом вернёт ошибку, и она показывается. Полный
  диалог ввода кода — отдельная задача.
* Ручная настройка прокси не пишется: писать в чужие конфиги KDE/GNOME хуже, чем честно показать
  переменные окружения.
* Профили VPN нельзя создавать и редактировать — только включать и выключать существующие.
* Ничего не проверено на живом железе: в песочнице нет ни NetworkManager, ни BlueZ, ни PipeWire.
