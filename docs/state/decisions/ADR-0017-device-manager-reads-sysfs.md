# ADR-0017 — «Диспетчер устройств» читает sysfs, а не базу вендоров

Дата: 2026-08-28. Статус: принято.

## Задача

Полноценный диспетчер устройств: ЦП, GPU, ОЗУ, плата, микропрограмма, диски, USB, PCI, звук, сеть,
Wi-Fi, Bluetooth, камера, мониторы, клавиатура, мышь, тачпад, принтеры — с настоящими данными
ядра и безопасными диагностическими действиями.

## Решение

`backend/zaldros_backend/devices.py` читает `/sys/bus/pci`, `/sys/bus/usb`, `/sys/class/*`, DMI,
`/proc/bus/input/devices`, `/proc/asound/cards` и очереди CUPS через `lpstat`. Ни `lshw`, ни
`hwinfo`, ни `lspci`: последний — это парсер над теми же файлами плюс двухмегабайтный `pci.ids`,
который мы не возим в ISO.

Три правила:

1. **Имя, которое не удалось разрешить, остаётся идентификатором** `dead:beef`. Идентификатор
   проверяем, придуманное маркетинговое имя — нет. Короткая таблица вендоров покрывает частые
   случаи и не притворяется полной.
2. **Нет привязанного драйвера — так и написано.** Отсутствие `device/driver` в sysfs — это тот
   же факт, который Windows показывает жёлтым треугольником, и он читается, а не угадывается.
3. **Пустая категория объясняет себя.** «ядро не показывает /sys/bus/pci/devices в этой среде» —
   это ответ; пустой список без объяснения выглядит как поломка. Категории, отсутствие которых
   само по себе информация (камера, принтер, монитор), показываются всегда.

Что отфильтровано намеренно: `lo` не сетевой адаптер, раздел не диск, `loop`/`zram` не диск,
корневые хабы `usbN` и интерфейсы `1-2:1.0` не устройства, отключённый выход DRM не монитор.

`rescan()` пишет в `/sys/bus/pci/rescan`; без root ядро отвечает EPERM, и это выводится дословно,
а не превращается в «готово».

## Дизайн

Окно закрыто по умолчанию, кнопка на панели появляется только пока оно открыто. Семь кадров
до/после отличаются только цифрами минут на часах панели (8×8 px, 08:44 → 08:54). Паритет 41/41.

## Чего нет

* Модули DIMM (DMI type 17), серийные номера и SPD требуют root — показан общий объём и это
  сказано в свойствах.
* Bluetooth-адаптеры перечисляются как PCI/USB-устройства; отдельной ветки с именем и состоянием
  из BlueZ пока нет (фасет `bluetooth` из ADR-0014 готов и будет подключён).
* Обновление и откат драйверов не делались: в Linux это модули ядра и пакеты, а половинчатая
  кнопка «обновить драйвер» хуже её отсутствия.
* На живом железе ничего не проверено: в песочнице нет ни шины PCI, ни USB, ни DRM — именно
  поэтому каждая ветка показывает причину.
