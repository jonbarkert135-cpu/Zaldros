# ADR-0015 — Каждый элемент «Параметров» — это контрол с чтением и записью

Дата: 2026-08-28. Статус: принято.

## Задача

Окно «Параметры» повторяло информационную архитектуру Windows 11, но почти каждый переключатель
был нарисованным прямоугольником: `toggle=True` в дереве страниц, клик — без последствий. Требование
владельца: **каждый переключатель меняет реальное состояние системы**, и проверяется цикл
UI → backend → состояние системы → UI показывает состояние.

## Решение

Между строкой «Параметров» и `zaldros_backend` появился один слой —
`shell/zaldros-shell/zaldros_shell/settingscontrols.py`. Он держит реестр контролов; у каждого есть
идентификатор, вид и две функции:

    клик ──► Control.write ──► zaldros_backend ──► служба Linux
                                     │
    строка ◄── Control.read ◄────────┘   (перечитывается после каждой записи)

Правила слоя:

1. **UI не хранит состояние.** После записи реестр перечитывает значение из системы и возвращает
   его. Если служба отказала, переключатель остаётся там, где его оставила служба, а в строке
   появляется причина.
2. **Четыре вида строк:** `switch`, `choice`, `action`, `info`. Ползунки (яркость, громкость,
   скорость указателя) сделаны как `choice` по дискретным шагам — это настоящая запись сегодня,
   вместо нового виджета когда-нибудь. Windows открывает здесь выпадающий список; мы открываем
   вложенную страницу тех же карточек с отметкой у текущего варианта: один визуальный язык, второй
   виджет не нужен.
3. **`info` тоже в реестре.** «Эту строку нельзя изменить» — записанный факт, а не умолчание.
4. **Каждое состояние несёт `available`, `writable` и `reason`.** Строка, которую машина не может
   выполнить, рисуется приглушённой, с причиной на месте значения и без шеврона.

## Что добавилось в backend

| Фасет | Служба | Первоисточник |
|---|---|---|
| `localetime` | timedate1, locale1 | systemd man `org.freedesktop.{timedate1,locale1}` |
| `inputdevices` | KWin `org.kde.KWin.InputDevice` | KDE/kwin `src/backends/libinput/{connection.cpp,device.h}` |
| `accounts` | accountsservice | `data/org.freedesktop.Accounts{,.User}.xml` |
| `permissions` | портал разрешений | xdg-desktop-portal `PermissionStore.xml`, `src/device.c`, `src/location.c` |
| `updates` | PackageKit | `src/org.freedesktop.PackageKit{,.Transaction}.xml` |
| `firewall` | ufw / firewalld | `/etc/ufw/ufw.conf`, firewalld D-Bus |
| `defaultapps` | `mimeapps.list` | freedesktop «Association between MIME types and applications» 1.0.1 |
| `power.firmware_setup` | logind | `SetRebootToFirmwareSetup`, `CanRebootToFirmwareSetup` |

Все прочитаны 2026-08-27/28, каждая ссылка записана в `catalog.py` рядом с именами.

## Отвергнутые варианты

- **Хранить значения в оболочке и «применять» их фоном.** Тогда UI показывает намерение, а не
  систему; ровно это и было сломано.
- **Свой ползунок сразу.** Новый виджет — это правка визуального гейта; дискретный выбор пишет
  настоящие значения и ничего не ломает.
- **Писать `/sys` и конфиги мимо служб.** Гонка с PowerDevil/NetworkManager и потеря polkit.
  Записываем только туда, где у изменения есть владелец.

## Последствия

- Каждый setter уходит в polkit с `interactive=true`: пользователь видит запрос пароля вместо
  молчаливого «не разрешено».
- Брандмауэр ufw меняется через `pkexec ufw`, потому что у ufw нет ни D-Bus, ни своего действия
  polkit. Это единственное место в «Параметрах», где мы запускаем внешнюю команду от root.
- Общий переключатель приватности пишет разрешение каждому приложению, которое уже спрашивало.
  Пустая таблица — не повод писать «wildcard», которого в базе портала нет; строка так и говорит.
