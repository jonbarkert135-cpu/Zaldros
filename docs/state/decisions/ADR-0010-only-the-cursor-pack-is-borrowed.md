# ADR-0010 — Of the third-party theme packs, only the cursors ship

**Status:** accepted, 2026-08-26. Narrows ADR-0007 point 2; everything else in ADR-0007 stands.

## Context
The owner asked why Zaldros is being built at all when Linuxfx/WindowsFX (now Winux, previously
Wubuntu) already exists, and whether its Windows-on-Linux result could simply be copied one to one.

Findings behind the answer:

- Winux/Wubuntu/Linuxfx is **proprietary and paid** (licence key, PowerTools suite). Its own
  components are not published as source, so nothing from it can be copied, forked or shipped.
- Its Windows-like desktop is, by its maintainer's own description, *Ubuntu with open-source Windows
  themes applied* on KDE Plasma. The Register's review calls the imitation skin-deep. There is no
  technical asset there that is both unique and available to us.
- Its history (2022 activation-database exposure of keys, e-mails and IPs; repeated rebrands;
  unresolved trademark exposure) makes it a bad thing to depend on even where copying were legal.

So the only reusable part of that approach is the same GPL-3 theme work anyone can take. The owner's
decision after that answer, on 2026-08-26: **take the cursors, draw everything else ourselves.**

## Decision
1. `fetch-sources.sh` clones exactly one upstream project, sparse-checked out to `cursors/`:
   `vinceliuice/Fluent-icon-theme` (GPL-3.0). Its prebuilt `dist` / `dist-dark` are copied
   unmodified, keeping the upstream names and licence file.
2. **No third-party GTK theme and no third-party icon theme are installed.** `Win11-gtk-theme` and
   `Win11-icon-theme` are removed from the image build.
3. The system icon theme `Zaldros` is generated by `install-visual-theme.sh` from `assets/icons/`
   in this repository, in freedesktop layout, so Qt, GTK and the shell resolve the same names.
4. GTK applications run on stock Adwaita with our design tokens applied through `gtk.css`. This is
   colour parity only and is recorded as such — no claim of Windows 11 parity for GTK apps.
5. Window decorations fall back to Breeze with no border until our own Aurorae theme exists. The
   placeholder is named in the component matrix rather than presented as done.

## Consequences
- One fewer moving part in the ISO and one fewer upstream that can change our look between builds.
- Pixel parity work now has a single owner: our QML shell plus our icon set. When a metric is wrong
  it is our file that is wrong, which is what makes `tools/visual/parity.py` meaningful.
- Cost: app, mime and device icon coverage is limited to what we vendor (17 app icons, 9 places,
  26 Fluent glyphs). Anything outside that set falls back to the lettered tile until we draw it.
- The app and place SVGs vendored in `assets/icons/` are themselves GPL-3 upstream work; their
  COPYING and AUTHORS are installed into `/usr/share/doc/zaldros/licenses/`. Replacing them with our
  own artwork is tracked in `TODO.md`, not assumed.
- `test_visual_layer.py` fails the build if a theme pack reappears or if a cursor theme is named in
  `visual.conf` without being installed.
