# Последовательность рабочих промптов

## Общий контракт — читать перед каждым Pxx

Ты развиваешь **Zaldros OS**: независимую Linux-систему со знакомыми пользователю
Windows рабочими сценариями и собственным брендом. Цель — рабочая система, а не только
похожая картинка. Исходная архитектура: Ubuntu 26.04, KWin 6/Wayland, Qt6/QML,
Python backend, NetworkManager/PipeWire/BlueZ/UPower/UDisks/logind/polkit,
LibreOffice для Office. Не начинай проект заново и не меняй стек без доказанной причины.

Перед работой:

1. Найди применимые AGENTS.md; прочитай CONTRIBUTING.md, docs/NAMING.md,
   docs/development/{README,AUDIT,PLAN,PROGRESS}.md, нужный Pxx и связанные ADR.
   Сначала проверь git status, HEAD, доступные инструменты и реальные файлы.
   Не считай текст старого отчёта свежим результатом тестирования.
2. Используй существующий checkout: облачная задача уже изолирована; worktree нужен
   только по явной просьбе. Сохрани пользовательские изменения. Никаких массовых reset,
   переписывания истории, лишней смены зависимостей и переписывания всего backend.
3. Выполняй один этап до его acceptance gate. Для большого этапа выдели один конкретный
   проверяемый подэтап и запиши оставшееся; не отмечай весь Pxx завершённым по его части.
   Кодовые изменения теперь допустимы в рамках выбранной задачи, но не делай их до
   воспроизведения проблемы и проверки существующего решения.
4. Clean-room: извлекай поведенческие требования из открытой документации и законно
   полученных наблюдений; пиши собственную реализацию или используй OSS по лицензии.
   Не копируй закрытые исходники, proprietary binaries/fonts/icons/wallpapers. Microsoft
   OSS допустим при соблюдении его лицензии. Не смешивай исследовательские референсы
   и поставляемые ресурсы. Фиксируй источник, версию, лицензию, изменения и notices.
   Этот процесс снижает риск, но не является юридическим заключением.
5. Проведи цепочку **UI → model → backend → служба → readback**. Не выдавай mock,
   screenshot, HTTP/PID/успешный D-Bus return за проверенную конечную функцию.
   Данные unavailable не заменяй выдуманными. Shell не запускается от root.
6. Долгие операции асинхронны, имеют deadline, состояние, понятную ошибку и границу
   отмены. Не дели один синхронный D-Bus socket между потоками без модели владения.
   Проверь success, denial, cancel, timeout, исчезновение устройства/службы и recovery.
7. Новые пользовательские строки извлекаемы для RU/EN; интерфейс управляется
   клавиатурой и показывает фактическое состояние. Не ухудшай функции/безопасность
   ради внешнего сходства или измерения RAM.
8. Запускай подходящие существующие тесты; добавляй регрессионный тест на реальный
   дефект. Сохраняй TLS, подписи, checksums. Не ослабляй проверки и не обновляй
   эталонное изображение только ради зелёного результата.
9. Не публикуй, не отправляй сообщения, не выполняй push и разрушительные операции
   над настоящими дисками без авторизации. Для системных изменений используй disposable
   VM/тестовые данные. Секреты не выводи и не сохраняй в код/артефакты.
10. Заверши PROGRESS.md: SHA/изменённые файлы, команды и исходы, counts/skips,
    артефакты, текущие ограничения, решения, точный следующий шаг. Если упёрся в среду,
    исчерпай независимую работу и укажи конкретный prerequisite; BLOCKED не равно DONE.
    Не оставляй только новый план там, где можешь закончить реализацию.

Минимальный регрессионный набор при изменениях общей логики:

```bash
source /workspace/.venvs/zaldros/bin/activate
export QT_QPA_PLATFORM=offscreen
export XDG_CACHE_HOME=/workspace/.cache/zaldros
export XDG_RUNTIME_DIR=/workspace/.local/run/zaldros
mkdir -p "$XDG_CACHE_HOME" "$XDG_RUNTIME_DIR"
chmod 700 "$XDG_RUNTIME_DIR"
cd /workspace/Zaldros
python -m pytest tools -q
cd shell/zaldros-shell
python -m pytest tests -q -rs
cd ../../tools/zaldros-compat
python -m zaldros_compat --check
```

Это путь подготовленной машины, а не универсальная установка. Если venv отсутствует,
используй актуальные setup-инструкции среды. В исходном запуске PIL отсутствовал,
поэтому visual context-menu suite пропускался; P03 должен разделить обязательные и
необязательные dependencies и устранить пропуски обязательных проверок.
Для Office нужен системный Python, совместимый с python3-uno; не объявляй его
проверенным по результату venv без UNO. Команды сборки ISO не запускай вслепую.

## P02 — Clean-room, лицензии и доверенная сборка

Примени общий контракт. Инвентаризируй реально поставляемые assets, темы, шрифты,
код и зависимости. Отдельно пометь research-only референсы. Создай provenance manifest
с путями, upstream URL/revision, лицензией, notices, модификациями и shipped-флагом;
не объявляй чужие assets разрешёнными только по названию пакета. Не удаляй неизвестные
ресурсы без анализа зависимостей и замены. Проверь F08: загрузка rootfs, подписанный
checksum manifest, доверенный fingerprint/keyring, digest до tar, отказ при mismatch,
чистый fallback. Не скачивай ключ и не принимай его на веру из того же непроверенного канала.
Готово: тест tampered archive и недоверенной подписи падает до распаковки; manifest
отделяет подтверждённые лицензии от нерешённых вопросов. Выпуск блокируют только
конкретные непроверенные поставляемые компоненты, юридические выводы не выдумывай.

## P03 — Воспроизводимость и CI, которому можно доверять

Примени общий контракт. Сопоставь README команд и активных workflow с actual tests.
Подготовь единый dev bootstrap, совместимые фиксированные зависимости и понятные
точки запуска без изменения пользовательской системы. Раздели fast unit/bus/render
и slow ISO/VM jobs. Добавь coverage триггеров backend/apps/assets; восстанови Office
jobs под подходящим системным Python/UNO. Обязательные Pillow/numpy/render проверки
не должны тихо пропускаться. Историческую Fedora container-сборку явно отдели от
выбранной Ubuntu-сборки. Проверь least-privilege workflow permissions.
Готово: команды работают из документированных директорий; mandatory job не зелёный
при нуле тестов/отсутствии движка; локальные результаты и непроверенный remote CI различены.

## P04 — Неблокирующий backend и восстановление событий

Примени общий контракт. Исследуй F03/F04: settings slots → synchronous calls,
Qt notifiers, lifecycle connection, match rules, cached owners, subprocess timeouts.
Сначала тестом воспроизведи зависшую службу и перезапуск шины/сервиса.
Сравни небольшой прототип собственного async транспорта с зрелой библиотекой,
включая Unix FD и лицензию; сохрани решение ADR без переписывания всех facets сразу.
Введи Operation lifecycle и один вертикальный срез, затем переведи обязательные
долгие действия. Формализуй владение connection и отмену. Не создавай вложенную
event-loop реентерабельность как скрытый способ «починить» freeze.
Готово: heartbeat GUI продолжает работать при timeout, поздний ответ не затирает
новую операцию, reconnect возвращает события без дублей/утечек; ошибки типизированы.

## P05 — Настоящие окна и сессия KWin

Примени общий контракт. Сопоставь fullscreen QQuickView, внутренние AppWindow Items
и существующие KWin scripts/tabbox. Выбери документированный механизм shell surfaces,
рабочей области и связи с внешними окнами; не вводи вторую независимую window manager
модель для тех же окон. Реализуй small slice с двумя внешними программами.
Готово в Wayland VM: запуск, focus, minimise/restore, close, Alt+Tab, taskbar и snap
отражают действительные окна; приложения не спрятаны fullscreen shell; shortcuts
работают вне shell focus. Offscreen оставь для регрессий, не как замену VM acceptance.

## P06 — Запуск приложений, закрепления и поиск

Примени общий контракт. Проверь desktop_entries.py против freedesktop Desktop Entry
и XDG precedence: desktop-id, Hidden override, Terminal, DBusActivatable, field codes,
TryExec, видимость, передача файлов и кавычки. Предпочти зрелый launcher там, где он
устраняет самописную спецификацию. Свяжи pinned/installed/running с P05, не с именем процесса.
Поиск сначала по приложениям и настройкам; файловый индекс не сканирует весь home
на GUI-потоке и уважает исключения. Готово: локализованные/дублирующие имена не ломают
идентичность, корректная программа открывает файл, ошибку запуска видно, external window
появляется в taskbar; тесты на override и injection/escaping.

## P07 — Сеть до конечного состояния

Примени общий контракт. Разбери поддерживаемые security modes, NetworkManager states,
polkit, секреты, сохранённые профили, VPN, DNS/proxy и состояние UI.
Сначала обеспечь Ethernet DHCP/DNS и обычную Wi-Fi сеть; SAE/enterprise либо реализуй
отдельно, либо явно обозначь unsupported до ввода пароля. AddAndActivateConnection
не означает Connected: отслеживай activation/failure/reason, connectivity отдельно.
Готово: success, wrong password, cancel, adapter removal и NM restart проверены;
никаких паролей в logs; reconnect сохранённого профиля после relogin; VM evidence
Ethernet отдельно от аппаратного Wi-Fi evidence.

## P08 — PipeWire: устройства, маршруты и события

Примени общий контракт. Проверь AudioFacet, parsers wpctl/pactl и UI bindings.
Определи один основной backend и событие изменения вместо stale reads/частого polling.
Реализуй смену default sink/source, mute/volume и per-app volume с readback.
Готово: второе приложение меняет громкость — UI обновляется; USB/headset hotplug,
удаление активного sink, daemon restart не оставляют неверный маршрут или freeze.
Loopback/виртуальные устройства годятся для integration; фактический звук/микрофон
проверяй на железе отдельно. Недоступный микрофон не показывается как успешно выключенный.

## P09 — Bluetooth с рабочим pairing-agent

Примени общий контракт. Исследуй BlueZ Agent1 и существующих агентов выбранной
сессии. Добавь корректный lifecycle одного агента, PIN/passkey/confirmation,
таймаут, отмену и освобождение агента. Не ставь blanket trust для неизвестного устройства.
Готово: scan → pair → connect → disconnect → forget подтверждены состоянием BlueZ;
отмена пользователем, неверный PIN и удаление адаптера дают корректный итог.
Тестовый daemon обязателен для негативных веток; клавиатура/мышь/гарнитура — отдельные
hardware records. Без адаптера закончи код/тесты и отметь аппаратный gate BLOCKED.

## P10 — Мониторы, DPI, безопасный ввод

Примени общий контракт. Используй KScreen/KWin, не геометрию одного QML canvas.
Настрой расположение двух выходов, primary, scale, mode и hotplug; согласуй panel/workarea.
Опасное изменение требует подтверждения с автоматическим откатом по таймауту,
crash и недоступности UI. Отключение последнего рабочего выхода не должно оставлять
пользователя без восстановления. Проверь XKB layouts, RU+Latin, focus и смену устройств.
Готово: mixed DPI/resize/unplug в VM, сохранение после relogin, rollback без видимого
UI; физические GPU/мониторы получают отдельный evidence, не заменяются virtio результатом.

## P11 — Файлы без потери данных

Примени общий контракт. Воспроизведи F09 на временных каталогах: dangling symlink,
symlink к каталогу, коллизия, permission error, разные FS, падение между metadata и move.
Доведи copy/move/trash/restore до явных atomicity/rollback ограничений, progress/cancel.
Проверь mount/unmount через UDisks, busy device и безопасное извлечение. MIME associations
согласуй с XDG, а open проверь через настоящее внешнее приложение из P06.
Готово: данные сохраняются при отказе и отмене, trashinfo соответствует объекту,
большой каталог не блокирует GUI. Тесты не трогают домашние файлы пользователя.

## P12 — Уведомления, снимки и запись экрана

Примени общий контракт. Проверь notification-server ownership, actions, replace_id,
expiration, DND/history; не конфликтуй с уже работающим системным сервером.
Проверь portal.py на реальных PySide6 API, Request Response, cancellation и Unix FD

Готово: независимый notify client вызывает действие; screenshot сохраняет правильный
экран; короткий screencast содержит декодируемые кадры, consent/deny/cancel/stop
проверены, закрытые sessions/FD освобождены. Заранее определён срок хранения истории.

## P13 — Учётные записи, login/lock и авторизация

Примени общий контракт. Раздели live/test автологин и installed-session policy.
Проверь PAM/logind/polkit agent, обычного пользователя, denied/challenge/cancel,
отдельно service-side полномочия; UI check не является границей безопасности.
Доведи смену прав/блокировки/имени, безопасные create/delete flows и защиту последнего
администратора; provisioning аккаунта не хранит пароль в командах/логах.
Проверь portal privacy wording: оно не блокирует произвольный unsandboxed процесс.
Готово: login/lock/unlock/logout и две разные учётные записи в VM; shell не root,
отмена авторизации ничего не меняет, реальные защитные ограничения покрыты тестами.

## P14 — Питание, suspend/resume и systemd

Примени общий контракт. Проверь capability discovery, inhibitors, политику закрытия
крышки, battery states и power profiles. Результат StartUnit/Suspend наблюдай до
желаемого состояния, а не только job path/ответа метода. После resume восстанови
сеть, аудио, события и экран, не заставляя перезапускать shell.
Готово: shutdown/reboot/logout проверены disposable VM; user services и ошибки
systemd видны; suspend/resume на выбранном ноутбуке с журналом и повторным циклом.
VM без battery/lid не доказывает laptop behavior. Не отключай inhibitors ради теста.

## P15 — Приложения и обновления с recovery

Примени общий контракт. Зафиксируй ADR: системные apt/PackageKit обновления и один
канал пользовательских приложений (исследуй Flatpak) с ясными границами доверия.
Расширь query/refresh до install/update/remove, progress, errors, reboot-required,
проверки подписи и блокировок package manager. Не называй apt атомарным обновлением.
Готово на snapshot VM: успешное обновление, lock busy, insufficient space, network
failure, отмена до безопасной границы и recovery после обрыва; повторная операция
не портит dpkg. Rollback либо реально реализован и проверен, либо явно не обещан.

## P16 — RU/EN, клавиатура и доступность

Примени общий контракт. Инвентаризируй строки Python/QML/backend, создай extract/build/
load translation pipeline; не пиши второй ручной словарь в каждом компоненте.
Проверь обе локали, длинные строки, системные форматы и сообщения ошибок.
Добавь focus order, Accessible roles/names, shortcuts, screen-reader совместимость,
high contrast и reduced motion. Готово: core workflow проходит без мыши в RU/EN;
проверена работа AT-SPI/screen reader в реальной сессии; масштабирование не обрезает
критические кнопки. Геометрический Windows parity не отменяет доступность.

## P17 — Сквозная alpha и выбор архитектурного варианта

Примени общий контракт. После P02–P16 собери доверенный ISO на подходящем хосте.
Сначала один вариант/профиль и весь alpha workflow из PLAN.md; только после него
расширяй full/services/legacy × low/mid/modern. Улучши ui-drive/uitest: узнаваемый
конечный результат и внешние окна, не «экран немного изменился».
Каждый artifact связан с SHA, package manifest, VM parameters и command exit codes.
Готово: функциональные операции/daemon restarts проходят, отсутствующие данные
не превращены в PASS, визуальные и поведенческие регрессии разделены. По измеренным
результатам оформи ADR варианта; TCG timings не выдавай за hardware performance.

## P18 — Установка и восстановление установленной системы

Примени общий контракт. Исследуй зрелый установщик и его лицензию до написания
собственного partitioner. Работай только с явно выбранными виртуальными дисками.
Раздели live/test и installed configuration, bootloader, аккаунт, язык, сеть,
опциональное шифрование по ADR-0005. Предусмотри понятное подтверждение стирания.
Готово: clean install → reboot без ISO → login; повторяемость на UEFI, recovery
после неудачного update/boot, проверенная резервная копия. Secure Boot заявляется
только после реального подписанного пути и теста, не по наличию UEFI image.

## P19 — Полезный Office и доказанная совместимость

Примени общий контракт. Запускай Writer/Sheets/Slides с реальным LibreOffice и UNO
совместимого интерпретатора. Выбери ограниченный набор DOCX/XLSX/PPTX/ODF/PDF fixtures
с разрешённой лицензией; проверь текст, формулы, структуры и round-trip, не только
создание файла/скриншота. Честно документируй потери формата и unsupported features.
Для Wine/Proton выбери ограниченный список приложений, версии, runtime и safe prefixes;
каждую compatibility claim обеспечь reproducer/evidence. Готово: engine jobs выполняют
тесты без skip, UI показывает настоящий документ; отсутствие Windows app evidence
не мешает alpha Linux desktop, но запрещает обещание её совместимости.

## P20 — Оборудование, измерения и выпуск

Примени общий контракт. Определи фактические устройства/драйверы для low/mid/modern,
GPU Intel/AMD/NVIDIA, Wi-Fi/BT, touchpad, external displays, suspend и storage.
Собери baseline → change → compare с версиями, variance и одинаковыми условиями;
нет сопоставимых данных — INCONCLUSIVE. Устрани утечки/лишние wakeups без урезания UX.
