# Аудит Zaldros OS — 2026-10-26

## Вывод

Zaldros — уже не только нарисованная оболочка. Есть существенный Python backend,
настоящие операции с файлами, PTY-терминал, чтение /proc и sysfs, адаптеры системных
служб, Qt/QML-интерфейс, код сборки ISO и VM-проверок. Наиболее важный следующий шаг —
связать эти части в проверяемый рабочий стол с настоящими внешними приложениями,
неблокирующими операциями и восстановлением после отказов.

«Полностью рабочий backend» сейчас не доказан. Метод, отправивший D-Bus-вызов,
не равнозначен завершённой системной операции; тест с MockSystem не равнозначен
проверке NetworkManager, BlueZ или logind на целевой ОС.

## Основание и пределы

Просмотрены архитектурные документы, актуальные workflow, backend, Qt bridge,
создание UI, модели, файловые операции, запуск .desktop, portal, сборка и тесты.
Это инженерный обзор исходников и локальных проверок, не полный security-аудит.
Ссылки на старые успешные CI-прогоны в BUILD.md — исторические заявления репозитория:
в этой сессии удалённые артефакты не проверялись, ISO не собирался и не загружался.

## Как устроен проект

Основной путь: QML → QObject-модели в `shell/zaldros-shell/zaldros_shell/` →
`ZaldrosBackend` → системные/сессионные D-Bus-службы, CLI, /proc и sysfs.
`backend/zaldros_backend/facade.py` агрегирует домены. `Reading` хранит доступность,
источник и объяснение отсутствия данных; `Result` — успех/ошибку вызова.
`qtbridge.py` подключает сокеты шин к Qt и объединяет события.
`testing.py` предоставляет тестовые службы на настоящем приватном dbus-daemon.
Это полезные интеграционные тесты транспорта, но сами службы в них имитируются.

| Область | Что уже есть | Что ещё нельзя считать доказанным |
| --- | --- | --- |
| Сеть | NM: состояние, scan, connect, сохранённые/VPN-профили, DNS/proxy чтение | Все варианты WPA/enterprise, секреты, завершение активации, восстановление после потери службы |
| Звук | wpctl/pactl, устройства, потоки, громкость, микрофон | Живые события PipeWire, hotplug, стабильная синхронизация внешних изменений |
| Bluetooth | BlueZ discovery/pair/connect/trust/remove | Пользовательский pairing-agent, PIN/подтверждение и реальные периферийные устройства |
| Питание/сессия | UPower/logind, профили, lock/layout | Suspend/resume и блокировка на целевом железе; защищённая login-сессия |
| Экран/ввод | KScreen/яркость, параметры устройств | Несколько мониторов/DPI, unplug, безопасный откат плохого режима |
| Диски/файлы | UDisks, browse/create/rename/trash/open | Полный цикл restore, сложные mountpoints/symlinks, отмена и прогресс больших операций |
| Учётные записи/приватность | accountsservice, polkit, portal permission store, firewall | Согласованный UX авторизации, защита последнего администратора, точная граница portal-разрешений |
| Обновления | PackageKit GetUpdates и RefreshCache | Установка обновлений, reboot-required, ошибка dpkg, recovery/rollback |
| Shell/окна | Start, taskbar, search UI, snap/Alt+Tab, встроенные приложения | Одинаковое поведение для независимых окон внешних программ под KWin |
| Диагностика | sysprobe/hwinfo/bench, boot/UITest/report, collect-logs | Корреляция «артефакт → SHA → сценарий → результат» для каждого актуального релиза |
| Office | Qt UI и мосты к LibreOffice | Полный round-trip реальных документов в этой среде; единый engine CI отсутствует в активном ci.yml |

## Конкретные находки

**F01. Документы противоречат текущему коду.** README, ROADMAP и REALITY_AUDIT
содержат ранние статусы; PROJECT_STATE одновременно хранит «нет сборки» и более поздние
сообщения о boot PASS. `docs/sheets/BUILD.md` описывает sheets job, которого нет в
активном `.github/workflows/ci.yml`. Сначала нужен актуальный реестр возможностей.

**F02. Два разных уровня окон.** `qml/AppWindow.qml` начинается с `Item`,
`Shell.qml` хранит фиксированные `windowIds` и их open/minimised/maximised состояния.
`app.run()` показывает один fullscreen QQuickView и берёт primaryScreen.
Значит, тестирование встроенного snap не доказывает управление внешними окнами или
multi-monitor. При этом уже есть KWin script/tabbox в `system/theme/`: сначала
исследовать и использовать его, а не объявлять интеграцию полностью отсутствующей.

**F03. Синхронный путь из UI.** `model.SettingsControls.state/activate/set` напрямую
вызывают Registry, далее системные методы. `Connection.call` ждёт ответ в цикле;
`UpdatesFacet._transaction` ждёт до 60/180 секунд, Wi-Fi connect — до 45 секунд,
firewall pkexec — до 120 секунд. Это риск блокировки GUI, установленный по коду;
конкретные задержки надо измерить fault-injection тестом и в VM. Решение — управление
асинхронной операцией, не бездумный перенос общей D-Bus connection в несколько потоков.

**F04. Recovery шины неполон на уровне архитектуры.** Bus пытается переподключиться,
но BackendBridge создаёт notifier при attach, а facade сохраняет установленные watch.
Переустановка match rules и notifier после смены connection/owner не доказана.
Нужен тест kill/restart тестовой службы и транспорта с проверкой возобновления событий.

**F05. Ограниченный Wi-Fi-контракт.** `network.connect_wifi` выбирает `wpa-psk`,
если пароль непустой, и возвращает результат AddAndActivateConnection.
Это не полная модель enterprise/SAE/скрытых сетей и не подтверждение доступа в интернет.
Нельзя обещать подключение сразу по успешному ответу метода.

**F06. Обновления пока только query/refresh.** В `updates.py` нет завершённого
install/update lifecycle. В `facade.DOMAINS` нет updates/firewall/apps, поэтому
событийный контракт этих областей требует отдельного решения. Atomic updates из
старых bootc-документов нельзя автоматически приписывать Ubuntu apt-системе.

**F07. CI пропускает важные изменения.** В `iso.yml` path filter включает build/iso,
shell, system/theme, workflow, но не backend, apps и assets. ci.yml запускает shell
и tools, а Office jobs отсутствуют. Нужно определить быстрый PR gate и отдельный
дорогой ISO/VM gate; не собирать девять VM после любой правки Markdown.

**F08. Цепочка доверия rootfs.** `build-iso.sh` скачивает BASE_TARBALL через HTTPS
и сразу передаёт tar. В просмотренном участке нет сверки с подписанным checksum
Ubuntu до распаковки. TLS остаётся включённым, но не заменяет проверку артефакта.
Планировать проверку подписи manifest доверенным ключом, digest и чистый fallback.
Не выполнять root-сборку до устранения/отдельной проверки этого пути.

**F09. Файловые крайние случаи.** `files.move_to_trash` пишет trashinfo перед move,
использует source.resolve() и source.exists(). Проверить dangling symlink, сохранение
самой ссылки, согласованность metadata при ошибке move, разные файловые системы,
коллизии и восстановление. Это вопросы для воспроизводящих тестов, не заявление
о доказанной потере данных. `DefaultAppsFacet` использует собственный разбор
mimeapps.list и фиксированный temporary path — нужен аудит XDG precedence/атомарности.

**F10. Запуск приложений упрощён.** `.desktop` parser удаляет field codes,
discover дедуплицирует по имени, launch использует shlex + Popen. Требуется проверить
Hidden override по desktop-id, вложенные desktop IDs, Terminal, DBusActivatable,
TryExec/OnlyShowIn и передачу файлов. Успешный Popen не доказывает появление окна.

**F11. Локализация и доступность отстают от требований.** В backend, Registry и QML
есть пользовательские русские строки; ADR-0005 требует извлекаемые tr/gettext и RU/EN.
Покрытие keyboard/focus, screen reader, reduced motion/high contrast не установлено.

**F12. Clean-room пока процесс, который нужно оформить.** В `THIRD_PARTY_LICENSES.md`
есть разрешённые открытые компоненты, включая Fluent UI MIT. Запрет на проприетарные
assets не означает запрет на весь Microsoft OSS. Однако утверждение сторонней темы
о GPL само по себе не доказывает происхождение каждого изображения. Нужен пофайловый
реестр, источники, лицензии, notices и разделение исследовательских референсов от
поставляемых assets. Юридическая чистота не подтверждается количеством тестов.

## Что сохранить

Переиспользование Linux/KDE/LibreOffice вместо собственного ядра и office engine;
Reading/Result и явное unavailable; приватный dbus-daemon для детерминированных тестов;
визуальные регрессии; фактические /proc/sysfs данные; отдельные boot и UI gates.
Не начинать с переписывания backend, смены дистрибутива или косметической перерисовки.
